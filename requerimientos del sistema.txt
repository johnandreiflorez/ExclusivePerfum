ESPECIFICACIÓN DE REQUERIMIENTOS FUNCIONALES
Sistema de Control de Ventas, Facturación, Cartera e Inversiones

Versión: 1.0
Fecha: 24/09/2026
Tecnología objetivo: Next.js + PostgreSQL + Capacitor
Tipo de aplicación: Web responsive + PWA + APK Android

1. OBJETIVO DEL SISTEMA

Desarrollar una aplicación para centralizar y sistematizar el control de las operaciones comerciales y financieras actualmente registradas manualmente.

El sistema deberá permitir gestionar:

Clientes.
Productos.
Ventas.
Costos asociados a las ventas.
Facturas.
Fechas y cuotas de pago.
Pagos y abonos.
Cartera.
Despachos.
Inversores.
Aportes de capital.
Participación de inversores en las ventas.
Cálculo y distribución de ganancias.
Gastos.
Flujo de caja.
Reportes.
Dashboard financiero.
Auditoría de operaciones.

El sistema deberá proporcionar trazabilidad completa desde la creación de una venta hasta su facturación, despacho, recaudo, cálculo de rentabilidad y distribución de ganancias.

4. MÓDULO DE AUTENTICACIÓN Y USUARIOS
RF-AUT-001 — Inicio de sesión

Descripción:
El sistema deberá permitir a los usuarios autenticarse mediante correo electrónico y contraseña.

Actor: Todos los usuarios.

Precondiciones:

El usuario debe estar registrado.
El usuario debe estar activo.

Flujo principal:

El usuario introduce correo electrónico.
Introduce contraseña.
El sistema valida las credenciales.
El sistema identifica los roles del usuario.
El sistema genera la sesión.
El usuario es dirigido al dashboard.

Reglas:

Las contraseñas deberán almacenarse utilizando hash seguro.
Las credenciales incorrectas no deberán revelar información sensible.
Un usuario inactivo no podrá autenticarse.
RF-AUT-002 — Cierre de sesión

El usuario podrá cerrar su sesión.

El sistema deberá invalidar la sesión correspondiente.

RF-AUT-003 — Gestión de usuarios

El administrador podrá:

Crear usuarios.
Editar usuarios.
Activar/desactivar usuarios.
Asignar roles.
Consultar usuarios.
RF-AUT-004 — Gestión de roles

El sistema deberá soportar roles y permisos.

Un usuario podrá tener uno o varios roles.

El sistema deberá permitir crear una venta.

Cantidades.

RF-VEN-002 — Numeración automática

El sistema deberá generar automáticamente un número único de venta.

Formato sugerido:

V-2026-000001

El número no podrá repetirse.

RF-VEN-003 — Agregar productos

Una venta podrá contener uno o varios productos.

Cada detalle deberá almacenar:

Producto.
Descripción histórica.
Cantidad.
Costo unitario.
Precio unitario.
Descuento.
Subtotal.
RF-VEN-004 — Cálculo del subtotal

El sistema calculará:

Subtotal = Cantidad × PrecioUnitario - Descuento

El valor no deberá ser digitado manualmente cuando pueda calcularse.

RF-VEN-005 — Costos de venta

El sistema permitirá registrar costos asociados a la venta.

Tipos:

Costo del producto.
Envío.
Seguro.
Comisión.
Empaque.
Impuestos.
Otros.
RF-VEN-006 — Cálculo de costo total

El sistema calculará:

CostoTotal = CostoProductos + CostosAdicionales

RF-VEN-007 — Cálculo de ganancia

El sistema calculará:

Ganancia = IngresoVenta - CostoTotal

RF-VEN-008 — Margen de ganancia

El sistema calculará el porcentaje de margen:

Margen = Ganancia / IngresoVenta × 100

RF-VEN-009 — Estados de venta

La venta deberá manejar como mínimo:

BORRADOR.
CONFIRMADA.
CANCELADA.
RF-VEN-010 — Modificación de venta

Una venta en estado BORRADOR podrá modificarse libremente.

Una venta CONFIRMADA tendrá restricciones.

Si ya tiene factura o pagos asociados, no podrá modificarse directamente en campos financieros sin autorización.

RF-VEN-011 — Cancelación

Una venta podrá cancelarse si cumple las reglas definidas.

La cancelación deberá quedar registrada en auditoría.

RF-FAC-004 — Cálculo del total

El sistema deberá calcular automáticamente:

Total = Subtotal - Descuentos + Impuestos + OtrosCargos

RF-FAC-005 — Saldo de factura

El sistema calculará:

Saldo = TotalFactura - TotalPagosAplicados

El saldo no podrá ser negativo.

RF-FAC-006 — Estado financiero

La factura deberá manejar:

PENDIENTE.
ABONADA.
PAGADA.
VENCIDA.
ANULADA.
RF-FAC-007 — Factura pagada

Una factura será considerada PAGADA cuando:

Saldo = 0

RF-FAC-008 — Factura abonada

Una factura será ABONADA cuando:

0 < TotalPagado < TotalFactura

RF-FAC-009 — Factura vencida

Una factura será considerada vencida cuando:

FechaActual > FechaVencimiento

y:

Saldo > 0

22. REGLAS DE NEGOCIO
RN-001 — Unicidad de venta

No pueden existir dos ventas con el mismo número.

RN-002 — Unicidad de factura

No pueden existir dos facturas con el mismo número.

RN-003 — Saldo de factura

El saldo será calculado por el sistema.

RN-004 — No sobrepago

Nunca podrá aplicarse un pago superior al saldo de una factura.

RN-005 — Integridad de cuotas

La suma de las cuotas no podrá superar el valor de la factura.

RN-006 — Integridad de participación

La suma de participaciones de una venta deberá cumplir la regla configurada.

Por defecto:

100%

RN-007 — Historial financiero

Los registros financieros no deberán eliminarse físicamente cuando tengan operaciones relacionadas.

Se utilizarán estados como:

ANULADO

RN-008 — Histórico de precios

Modificar el precio de un producto no modificará ventas históricas.

RN-009 — Cálculos automáticos

Los siguientes valores deberán calcularse automáticamente:

Subtotales.
Total factura.
Saldo.
Ganancia.
Margen.
Ganancia del inversor.
Saldo de inversión.
RN-010 — Factura vencida

Una factura pendiente cuyo vencimiento haya pasado será identificada como vencida.

RN-011 — Trazabilidad

Todo movimiento financiero deberá poder relacionarse con su origen.

Ejemplo:

Pago
 ↓
Factura
 ↓
Venta
 ↓
Cliente
RN-012 — Trazabilidad de inversión

El sistema deberá poder responder:

¿De dónde salió el capital utilizado
para financiar esta venta?

Por lo tanto, las inversiones y participaciones deberán conservar su relación histórica.

Se pueda crear un producto.

Se puedan registrar costos.
Se pueda generar una factura.
Se puedan configurar fechas de pago.
Se puedan registrar pagos parciales.

Al cobrar.
